# INVEST-001: публичный Telegram-канал

Статус: **в работе** - сделано 2026-11-15, этап 15 [дорожной карты](../../roadmap.md). Код не закоммичен; ветка - та,
на которой сейчас репозиторий: invest-api `feature/INVEST-001` (отдельную ветку называет владелец). Проверено тестами
(Testcontainers); на стенде k3d и в настоящем канале не проверялось - канал по умолчанию выключен.

## Цель

Бесплатный канал привлечения: бот сам публикует в публичный канал короткие посты о событиях рынка облигаций, у каждого
поста - ссылка на страницу продукта.

## Объём

- **invest-api** - пакет `channel` модуля `feature/telegram-bot`, публикует тот же бот, что шлёт уведомления:
  - **рейтинговые действия** АКРА и НКР по эмитентам и выпускам из системы: присвоение, повышение, понижение, отзыв
    (подтверждения и прогнозы - нет); ссылка - страница эмитента или облигации;
  - **решения по ключевой ставке** (пресс-релизы ЦБ); ссылка - подборка флоатеров;
  - **еженедельная подборка** самых доходных облигаций по группам рейтинга (понедельник, 11:00 МСК); ссылки - страницы
    облигаций и список облигаций;
  - очередь постов `channel_post`, лимит постов в день, пауза между постами, окно публикации, срок актуальности - всё в
    конфигурации; шаблоны текстов без оценочных суждений.
- **invest-gateway, invest-api-ui** - без изменений: ссылки ведут на уже публичные SEO-страницы (`/bonds/{тикер}`,
  `/issuers/{id}`, `/collections/{slug}`, `/bonds`).
- **Новые размещения** - не сделаны: этап 14 (календарь размещений) остановлен, источника нет. Когда появится -
  ещё один вид поста по тем же правилам.

## Готово, когда

- [x] пост не дублируется при перезапуске: ключ поста (`RATING_ACTION:<id новости>`, `KEY_RATE:<id новости>`,
  `WEEKLY_TOP:<год>-W<неделя>`) уникален в БД, статус публикации хранится там же; повторный сбор и публикация после
  отправки ничего не дают (`TelegramChannelTest.ratingActionIsPostedOnceAndNotRepeatedAfterRestart`,
  `weeklyTopByRatingGroupsOncePerWeek`);
- [x] при выключенном флаге (`ru.invest.api.telegram.channel.enabled: false`) в канал ничего не уходит - и новые
  посты не собираются, и стоящие в очереди не публикуются (`disabledChannelSendsNothing`);
- [x] лимит постов в день, пауза, окно публикации, пропуск устаревших, повтор после сбоя сети
  (`postingWindowDailyLimitAndPause`, `stalePostIsSkipped`, `networkErrorIsRetried`);
- [x] какие рейтинговые действия идут в канал - на настоящих формулировках агентств (`TelegramChannelRulesTest`);
- [x] на стенде k3d (2026-11-15, канал выключен, бот включён): под стартует без ошибок, миграция `channel_post`
  (колонки, уникальный ключ, индексы), шедулер публикации берёт ShedLock; рейтинговая новость по эмитенту из системы
  при выключенном канале не даёт поста; лента новостей и новости эмитента отвечают, правила уведомлений без ошибок;
- [ ] проверка в настоящем канале: бот - администратор канала, `TELEGRAM_CHANNEL_*` заданы. На стенде релизы АКРА не
  загружаются (источник недоступен из кластера) - пост о рейтинге там придёт только от НКР.

## Как включить

1. Создать публичный канал, добавить бота (`TELEGRAM_BOT_USERNAME`) администратором с правом публикации.
2. `TELEGRAM_CHANNEL_ENABLED=true`, `TELEGRAM_CHANNEL_CHAT_ID=@имя_канала`, `TELEGRAM_CHANNEL_SITE_URL=https://<сайт>`
   (адрес, где открыты публичные страницы: до решения 0.1 и включения публичного режима ссылки будут вести на вход).
3. Бот должен быть включён (`TELEGRAM_BOT_ENABLED=true`): без него канала нет.

## Ограничения

- Рейтинговое действие видно только по заголовку релиза (тексты - в PDF) и только у АКРА и НКР: Эксперт РА и НРА к
  ленте не подключены. Релиз об эмитенте, которого нет в системе, не публикуется - у поста не было бы страницы.
- Пост, отправленный в Telegram, но не отмеченный в БД (приложение упало между отправкой и записью), при следующей
  публикации уйдёт повторно - окно в доли секунды; ShedLock не даёт двум экземплярам публиковать одновременно.
- Подборка в понедельник пропускается, если в 11:00 МСК приложение не работало (как дайджест портфеля).
- Посты не редактируются и не удаляются автоматически: `message_id` хранится, чтобы найти пост вручную.
- Публичных страниц без входа нет, пока публичный режим не включён на публичном адресе (решение 0.1) - до этого канал
  включать не стоит.
