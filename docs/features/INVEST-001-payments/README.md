# INVEST-001: Оплата

Статус: **в работе** - сделано 2026-11-13, этап 7 [дорожной карты](../../roadmap.md). Код не закоммичен; ветки - те,
на которых сейчас репозитории: invest-api `feature/INVEST-001`, invest-gateway `test`, invest-api-ui `feature/INV-001`
(отдельную ветку называет владелец).

## Цель

Пользователь сам покупает и продлевает тариф: оплата картой, автопродление по сохранённой карте, отмена
автопродления, история платежей.

## Объём

- **invest-api** - новый модуль `feature/payment-service`:
  - провайдер за интерфейсом `PaymentProvider` (как `NotificationSender` у уведомлений); первая реализация -
    **Т-Касса** (интернет-эквайринг Т-Банка, API v2): платёж со страницей оплаты и сохранением карты, списание по
    сохранённой карте, запрос статуса, webhook с проверкой подписи `Token`;
  - цена и срок - у тарифа (`price`, `period` в `ru.invest.api.plans`), настройка оплаты - `ru.invest.api.payments`,
    по умолчанию выключена;
  - таблицы `payment` (история, статус, выданная подписка) и `account_auto_renewal` (сохранённая карта, когда
    списать), колонка `account_subscription.payment_id`, новый источник подписки `PAYMENT`;
  - идемпотентность: платёж применяется под блокировкой строки, тариф выдаётся только при переходе в `SUCCEEDED`;
  - автопродление: шедулер раз в час списывает за сутки до конца срока, неудача - повтор через сутки, после трёх
    подряд автопродление отключается; ручная выдача и отзыв тарифа его отключают;
  - REST: `POST/GET /account/payments`, `GET /account/payments/{id}` (с уточнением статуса у провайдера),
    `DELETE /account/auto-renewal`, оплата в `GET /account/plan`; webhook `POST /payments/notifications/{provider}`;
    maintenance - платежи пользователя и запуск автопродления.
- **invest-gateway** - маршрут `/api/payments/notifications/**` без входа и без CSRF, не под лимитом анонимных
  запросов; `robots.txt` закрывает `/api/payments`.
- **invest-api-ui** - на странице «Тариф»: цена в сравнении, «Купить» / «Продлить» с согласием с офертой и политикой
  персональных данных, переход на страницу оплаты, итог оплаты после возврата (`/plan?payment=<id>`, опрос статуса),
  автопродление и его отключение, история платежей; цели Метрики `plan_checkout_started`, `plan_paid`.

## Готово, когда

В тестовом режиме провайдера (мок HTTP Т-Кассы, webhook с настоящей подписью) - `PaymentTest`:

- [x] оплата включает тариф - `confirmedNotificationGrantsPlanOnce`;
- [x] повторный webhook не продлевает его дважды - там же (одна подписка, срок тот же);
- [x] отмена останавливает автопродление - `cancelledAutoRenewalDoesNotCharge`;
- [x] неудачный платёж не меняет тариф - `failedPaymentDoesNotChangePlan`, `failedRenewalsDisableAutoRenewal`;
- [ ] проверка на тестовом терминале Т-Кассы (DEMO) вручную - нужен терминал владельца;
- [ ] решения владельца до включения: 0.1 (можно ли брать деньги за данные), 0.2 (статус для приёма платежей и
  провайдер - выбрана Т-Касса как заготовка), 0.5 (оферта и политика персональных данных - их адреса в
  `offer-url` / `privacy-url`).

Правила - в [business-rules.md](../../business-rules.md#оплата-тарифов), как сделано - в [design.md](design.md).

## Что осталось

- Решения 0.1, 0.2, 0.5 и проверка на тестовом терминале; затем `PAYMENTS_ENABLED=true` и ключи терминала.
- Фискальные чеки (54-ФЗ) зависят от статуса из 0.2: самозанятому - чек в «Мой налог», ИП / юрлицу - онлайн-касса
  (объект `Receipt` в Init Т-Кассы, нужен e-mail или телефон покупателя - gateway его пока не передаёт). Сейчас
  пользователь видит историю платежей, фискального чека нет.
- Оплата через Telegram Stars в боте (по желанию, роадмап) - не сделано.
- Возврат денег - только в личном кабинете Т-Кассы; webhook `REFUNDED` отзывает подписку платежа.
- PR в master вместе с INVEST-001.
