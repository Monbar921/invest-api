# SEO-страницы: устройство

## Как поисковик получает готовый HTML

Выбран **рендер метаданных и содержимого в gateway**: на запрос страницы облигации, эмитента, подборки или списка
gateway берёт `index.html` собранного UI (в нём ссылки на бандл с хешами), заменяет в `<head>` title и description,
добавляет canonical, Open Graph, `robots`, а в `<div id="root">` кладёт простой семантический HTML: заголовок, `<dl>`
с ценой, доходностью, купоном и датами, таблицу выпусков, новости, ссылки. Браузер загружает SPA как обычно, React
при монтировании заменяет содержимое `#root` своим.

```
браузер / поисковик ──▶ ingress ──▶ gateway (seo-service) ──▶ invest-api: /internal/rest/bonds/...
                                          └─▶ nginx UI: /index.html (кэш 1 мин)
```

Почему так:

- **поисковик и человек получают одно и то же** - тот же текст, что SPA потом отрисует (не cloaking);
- **не меняется стек UI**: Mantine, TanStack Query и React Router остаются в режиме SPA, ничего не переводится на SSR;
- **данные свежие**: цены меняются в течение дня - страница строится на запрос из тех же эндпоинтов, что у UI
  (у invest-api они из кэша);
- **gateway уже BFF**: он стоит на том же origin, знает публичный адрес сайта (`X-Forwarded-*`) и пропускает гостя;
  invest-api остаётся без HTML и без знания о UI.

Отвергнуто:

| Вариант | Почему нет |
| ------- | ---------- |
| пререндер при сборке | тысячи облигаций и ежедневные цены: пересборка UI при каждой синхронизации, устаревший HTML между сборками |
| отдельный рендер-сервис (headless Chrome) | тяжёлый сервис (сотни МБ памяти на браузер), задержка рендера, ещё один компонент на стенде |
| переход на SSR (React Router framework mode / Next.js) | переписать роутинг, загрузку данных и сборку; Mantine и графики - на сервере; Node-сервер вместо nginx. Несоразмерно задаче |
| HTML в invest-api | invest-api отдаёт данные и не должен знать о сборке UI; ему пришлось бы ходить в nginx за `index.html` |

Цена решения: разметку SEO-страницы gateway строит сам (`SeoPageBuilder`), она проще, чем у SPA, и её надо держать
согласованной с UI вручную - title и description на обеих сторонах строятся по одним правилам
(`SeoPageBuilder` в gateway, `bondMeta` / `issuerMeta` и `usePageMeta` в UI).

### Детали рендера

- `UiTemplateProvider`: `index.html` держится в памяти `invest.gateway.seo.template-ttl` (1 минута - после выкладки UI
  новые имена бандлов подхватываются быстро). UI не ответил - последний полученный; если его ещё не было - минимальная
  оболочка без скриптов (поисковику достаточно). Ответ без `id="root"` (страница-заглушка) не принимается.
- Всё, что пришло из invest-api, экранируется (`HtmlUtils.htmlEscape`): названия и заголовки новостей - внешние данные.
  Ссылка на новость - только для `http(s)`-адреса, другие схемы (`javascript:`) - просто текст заголовка.
- Содержимое кладётся в пустой `<div id="root"></div>`; если в `#root` что-то есть - в его начало, если `#root` нет -
  сразу после `<body>`: `#root` на странице всегда один.
- Значения, которых нет (доходность флоатера, оферта), на странице не показываются вовсе, а не прочерком и не
  приблизительно.
- Неизвестная облигация, эмитент или подборка - `404` с `noindex` и без canonical; оболочка та же, SPA покажет свою 404.
- invest-api не ответил - `503` с `Retry-After: 60` и оболочкой без содержимого: человек получает работающий SPA, а
  поисковик не запоминает пустую страницу. Новости - дополнение: их ошибка страницу не ломает.
- canonical и `og:url` - без query: `/bonds?ofz=only` и `/collections/x?page=2` указывают на страницу без параметров.
- Адрес сайта - `invest.gateway.seo.public-url`, а если не задан - из запроса (`ForwardedHeaderFilter`).

## Доступ и лимит

Пути `/bonds`, `/bonds/*`, `/issuers/*`, `/collections/*`, `/sitemap.xml`, `/robots.txt` (`SecurityConfiguration.PUBLIC_PAGES`)
открыты для `GET`/`HEAD` без входа - вместе с публичным режимом. Более глубокие пути (`/bonds/x/y`) - как раньше, через
логин. SEO-страница облигации содержит те же цену и доходность, что API, поэтому `AnonymousRateLimitFilter` считает и
её: у гостя один запас на API и страницы. Поисковики ходят с разных адресов и с паузами - 120 запросов в минуту на IP
их не ограничивают; если начнут - поднять лимит или исключить их по проверенному обратному DNS.

## robots.txt и sitemap.xml

- `robots.txt` закрывает личные разделы (`/portfolio`, `/alerts`, их API, `/api/session`) и вход. `/api/bonds` открыт
  намеренно: поисковик, исполняя SPA, сам запрашивает данные - если их закрыть, отрисованная им страница будет пустой.
- `sitemap.xml` - один файл (лимит протокола 50 000 адресов, облигаций - тысячи): `/bonds`, подборки, все облигации из
  кэша invest-api, эмитенты, у которых есть выпуск в системе. `lastmod` не указывается: честной даты изменения страницы
  нет (цена меняется каждый день), а неточный `lastmod` поисковики перестают учитывать. invest-api не ответил - `503` с
  `Retry-After: 60`, как у страниц: пустой sitemap с `200` поисковик понял бы как «страниц больше нет».

## invest-api

- `IssuerUseCase` (news-supplier): эмитент - строки `bond_issuer` с одним `emitter_id`; название и ИНН - из первой
  заполненной строки; выпуски - облигации из кэша с ISIN эмитента, по дате погашения. Строк нет - `404`.
- Новости эмитента - `NewsRepository.findByEmitterId`: ссылка на эмитента или на любой его ISIN.
- Сокращение формы собственности («ПАО», «АО», «ООО») вынесено в `IssuerTitles` - им пользуются и лента, и эмитент.
- Подборки - `BondCollection` (bond-supplier): slug, заголовок, описание и `BondParametersRequestModel` на дату.
  Страница подборки идёт через `BondUseCase.getAllPage` - те же фильтр, сортировка и пагинация, что у списка.
- `GET /bonds/sitemap` - только данные; адреса строит gateway: он знает публичный адрес сайта.
- Все новые эндпоинты - под `/bonds/**`, только чтение и без пользователя: gateway пропускает их гостю.

## invest-api-ui

- `lib/seo.ts`: `usePageMeta` меняет существующие теги (title, description, robots, canonical, og:*) - без дублей
  с тегами, которые пришли от gateway; пока данные грузятся - ничего не трогает. Значения нет - тег удаляется, чтобы
  не остался от прошлой страницы.
- Личные страницы (портфель, уведомления) и 404 - `noindex` без canonical.
- `FixedOrderBondsTable` - колонки списка облигаций без сортировки: порядок задаёт бэк (подборка, выпуски эмитента).
