# Аналитика и лендинг: устройство

Меняется invest-api-ui, плюс в invest-deploy включена саморегистрация в realm Keycloak (`registrationAllowed`) -
иначе «Зарегистрироваться» на лендинге вела бы на форму без регистрации. invest-api и gateway не тронуты: `/` уже отдаёт `index.html` UI (ingress →
nginx), а номер счётчика задаётся при `npm run build`, который `deploy.ps1 ui` запускает на машине.

## Аналитика (`lib/analytics.ts`)

Весь остальной код знает только `trackPageView(path)`, `trackGoal(goal, params)`, `readConsent()` / `saveConsent()` и
`analyticsEnabled()`. Сервис за ними - Яндекс Метрика; смена сервиса меняет один файл.

- **Номер счётчика** - `VITE_YANDEX_METRIKA_ID` при сборке (не секрет, но и не в коде: у стенда и продакшена разные
  счётчики). Не задан или не целое положительное число - аналитика выключена целиком, баннера нет.
- **Согласие.** Метрика ставит cookie, поэтому `tag.js` вставляется в `<head>` только после «Принять». Выбор - в
  `localStorage` (`invest.analytics-consent`); хранилище недоступно (приватный режим) - выбор действует до перезагрузки,
  потом баннер спросит снова. До согласия события не копятся: иначе отправились бы действия, сделанные до согласия.
  Исключение - просмотр текущей страницы: он отправляется в момент согласия, иначе страница входа на сайт терялась бы.
- **Инициализация:** `defer: true` (первый просмотр отправляет сам UI, а не Метрика при загрузке), `trackLinks`,
  `accurateTrackBounce`; `webvisor: false` и `clickmap: false` - запись сессий захватывала бы введённое в формы: суммы
  покупок, пороги уведомлений.
- **Просмотры** - эффект в `AppLayout` на смену `pathname`/`search`: `ym(id, 'hit', url, { referer })`, referer -
  прошлая страница SPA. Повтор того же адреса не считается. Вошедший на `/` не считается - его сразу уводит на
  `/bonds`, лендинг он не видел.
- **Цели** - `ym(id, 'reachGoal', goal, params)`, места вызова:
  - `bond_filter` - `BondsPage`, обработчик `BondFilters` (вкладки, сортировка и страницы - не фильтр);
  - `profit_calculation` - `ProfitCalculator`, первый успешный расчёт для тикера: расчёт перезапрашивается на каждое
    изменение поля, и иначе один пользователь давал бы десятки целей;
  - `portfolio_position_added`, `alert_rule_created` - `onSuccess` мутаций создания в `api/queries.ts`: одно место для
    всех кнопок, которые создают покупку или правило;
  - `telegram_connected` - `TelegramPanel`: статус стал `linked`, пока была выдана ссылка; уже подключённый Telegram при
    открытии панели целью не считается;
  - `landing_login` - кнопка лендинга.

### Отвергнуто

- **Self-hosted (Matomo, Umami).** Без cookie баннер не нужен, но это ещё один сервис с БД в k3d и на продакшене - ради
  счётчиков, которые Метрика даёт бесплатно. Если владелец решит иначе, меняется только `lib/analytics.ts`.
- **Код счётчика прямо в `index.html`.** Грузился бы до согласия и без возможности выключить сборкой.
- **Тикер в целях покупки и правила.** Вместе с идентификатором посетителя Метрики это раскрывало бы, что лежит в
  портфеле. Тикер остаётся только в адресе страницы, которую смотрят и гости.
- **Очередь событий до согласия.** Отправлять после «Принять» то, что человек делал до него, - против смысла согласия.

## Лендинг

- Маршрут `index` → `HomePage`: сессия известна до рендера (`window.investSession`), поэтому выбор мгновенный, без
  мигания: гостю `LandingPage`, вошедшему `<Navigate to="/bonds" replace />` - как было для всех.
- Метаданные: title «Облигации» (название сайта без суффикса), description, canonical `/`. Gateway `/` не рендерит
  (это не SEO-путь) - поисковик получает SPA; при необходимости `/` добавляется в `seo-service` отдельно.
- Возможности - статичный список в `LandingPage`; открытые гостю ведут в раздел, личные помечены «после входа».
- Живой пример: первая подборка из `GET /api/bonds/collections` и её первые 5 облигаций. Подборок нет или бэк не
  ответил - блока нет, лендинг работает и без бэка.
- Вход - `login()` с `returnTo=/`: после входа gateway вернёт на `/`, а оттуда `HomePage` уведёт на `/bonds`.

### Отвергнуто

- **Скриншоты.** Устаревают с каждым изменением интерфейса и требуют стенда с данными для съёмки; живой пример
  показывает то же на настоящих данных.
- **Лендинг на отдельном адресе (`/about`).** Гость, пришедший на корень сайта, всё равно должен увидеть объяснение, а
  поисковый трафик на облигации и подборки идёт сразу на их страницы.
