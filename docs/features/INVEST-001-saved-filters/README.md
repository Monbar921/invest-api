# INVEST-001: сохранённые фильтры и уведомления по фильтру

Статус: **в работе** - сделано 2026-11-15, этап 11 [дорожной карты](../../roadmap.md). Ветки - те, на которых сейчас
репозитории: invest-api `feature/INVEST-001`, invest-api-ui - текущая (отдельную ветку называет владелец). Проверено
тестами (бэк - Testcontainers, UI - Vitest) и в браузере на стенде k3d 2026-11-15.

## Цель

«Сообщи, когда появится облигация под мои условия»: пользователь сохраняет фильтр списка облигаций и получает в
Telegram сообщение, когда в выборку входит новая облигация.

## Объём

- **invest-api**
  - Сохранённые фильтры: название (уникально у пользователя без учёта регистра), вид (`ALL` / `LOCAL` / `FOREIGN`),
    параметры `BondParametersRequest` - фильтры и сортировка; таблица `saved_filter`, CRUD
    `/internal/rest/alerts/filters`. Лимит по тарифу - новый лимит `SAVED_FILTERS` (заготовка до решения 0.4:
    бесплатный - 5, премиум - 50).
  - Новый тип правила уведомлений `SAVED_FILTER` - строка `bond_alert` с `filter_id`; включается и выключается
    переключателем у фильтра (`notify`), занимает место в лимите правил `ALERTS`, выключается кнопкой в Telegram как
    любое правило. Через `POST /alerts` не создаётся (`422`).
  - Проверка после каждого обновления цен (`PricesSyncedEvent`, тот же слушатель, что у порогов цены): выборка
    сравнивается с прошлой (`saved_filter_match`), новые облигации - одно уведомление со списком (не больше
    `filter-max-bonds`, остальные - «и ещё N») через очередь `notification`.
  - Запас у границ фильтра, как у порогов цены: облигация выходит из выборки, только когда не проходит фильтр с
    расширенными диапазонами (цена, доходность, спред, дюрация, оборот) - колебание у границы не даёт потока сообщений.
- **invest-gateway** - без изменений: эндпоинты под `/api/alerts/**`, маршрут и пользователь из сессии уже есть.
- **invest-api-ui**
  - Над таблицей облигаций - «Мои фильтры»: сохранённые фильтры (открыть одним кликом, на кнопке - имя открытого,
    число облигаций в выборке, колокольчик у фильтров с уведомлениями), «Сохранить текущий фильтр» - название и
    «Сообщать о новых облигациях в выборке». Гостю не показывается.
  - На странице «Уведомления» - карточка «Фильтры облигаций»: ссылка на выборку, число облигаций, переключатель
    уведомлений, удаление с подтверждением. Правило `SAVED_FILTER` в списке правил не показывается отдельно.
  - Тариф: строка «Сохранённые фильтры» в лимитах. Цель аналитики `saved_filter_created`.

## Готово, когда

- [x] облигация, вошедшая в выборку после обновления цен, даёт одно уведомление - `SavedFilterTest.notifiesOnceAboutBondEnteringSelection`;
  выборка при включении уведомлений и после изменения параметров - отправная точка, не уведомление
  (`notificationToggleAndAlertRule`, `newParametersStartFromCurrentSelection`);
- [x] колебание около границы фильтра не даёт потока сообщений - `oscillationAroundBoundaryDoesNotRepeat`
  (доходность 20,05 → 19,95 → 20,02 - одно уведомление; ушла за запас и вернулась - второе);
- [x] CRUD, лимит по тарифу (`402`, `limit: SAVED_FILTERS`), лимит правил при включении уведомлений, удаление фильтра
  с правилом без потери истории - `SavedFilterTest`; UI - `savedFilters.test.tsx`;
- [x] на стенде k3d (2026-11-15): гость без меню, сохранение и открытие фильтра, повтор названия, переключатель и
  удаление на странице «Уведомления», лимит `402` на бесплатном тарифе, уведомление после синхронизации цен
  (статус «Отправлено», сообщение пришло в бот), экран 375px без горизонтальной прокрутки.

## Ограничения

- Проверка только после обновления цен: облигация, вошедшая в выборку из-за нового рейтинга (лента новостей) или
  ночной синхронизации купонов, попадёт в уведомление при ближайшем обновлении цен.
- Облигация, у которой пропало значение фильтра скринера (доходность не посчитана, нет свечей), выходит из выборки:
  когда значение вернётся, уведомление о ней придёт снова.
- Фильтр по дате погашения (`maturityDate`) сохраняется и проверяется, но в UI такого фильтра нет.
