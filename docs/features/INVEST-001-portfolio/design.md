# INVEST-001: портфель - устройство

```
UI /portfolio ──▶ invest-gateway /api/portfolio/** ──X-User-Id──▶ invest-api /internal/rest/portfolio/**
                                                                    │
                                              PortfolioController (ui-service)
                                                                    │
                          PortfolioUseCase (portfolio-service) ──▶ portfolio_position
                                                                    │
                                   BondUseCase.getByTickers ──▶ bond + price (одним запросом)
```

## Модули

- `feature/portfolio-service` - новый модуль: `PortfolioUseCase` (CRUD, расчёт стоимости и дохода, итоги), модели
  `PositionModel`, `PortfolioModel`, `PortfolioTotalModel`, `PositionRequestModel`. Зависит от `bond-supplier`.
- `common` - сущности `PortfolioPosition`, `PortfolioBroker`, репозитории `PortfolioPositionRepository`,
  `PortfolioBrokerRepository`; в `BondRepository` -
  `findWithPriceByTickerIn` (облигации с ценой и купоном по списку тикеров); код ошибки `PORTFOLIO_INVALID`.
- `tinkoff-supplier` / `bond-supplier` - `TinkoffBondUseCase.findByTickers`, `BondUseCase.getByTickers`: облигации
  портфеля читаются одним запросом из БД, мимо кэша, без рублёвой цены (`currentInRub` портфелю не нужна).
- `ui-service` - `PortfolioController`, `PortfolioDtoMapper`.
- `invest-api-dto` - пакет `ru.invest.api.dto.portfolio`.

## БД

Таблица `portfolio_position` (миграция `tables/012-portfolio.xml`): `user_id` (sub Keycloak), `ticker` без внешнего
ключа (облигации пересоздаются синхронизацией), `quantity`, `buy_price` (% от номинала, `numeric(10,4)`),
`buy_date`, `created_at`, `updated_at`. Индекс по `user_id`. Уникальности по тикеру нет - покупок одной облигации
может быть несколько.

Таблица `portfolio_broker` (второй changeSet того же файла): `user_id`, `name`, `created_at`; уникальный индекс
`(user_id, lower(name))`. У `portfolio_position` - `broker_id` с внешним ключом `on delete set null`.

## API

| Метод и путь                                     | Что                                                                |
| ------------------------------------------------ | ------------------------------------------------------------------ |
| `GET /internal/rest/portfolio`                   | `{groups, totals}`: строка на облигацию с покупками, итоги по валютам |
| `POST /internal/rest/portfolio/positions`        | `{ticker, quantity, buyPrice, buyDate?, broker?, buyAmountRub?}` → `201` |
| `PUT /internal/rest/portfolio/positions/{id}`    | `{quantity, buyPrice, buyDate?, broker?, buyAmountRub?}`; тикер из тела не используется |
| `DELETE /internal/rest/portfolio/positions/{id}` | `204`                                                              |
| `GET /internal/rest/portfolio/brokers`           | брокеры пользователя по имени `[{id, name}]`                       |

Брокер в покупке передаётся **именем** (`broker`), а не id: use case ищет его у пользователя без учёта регистра и
пробелов по краям, не нашёл - создаёт (не больше 50 у пользователя, иначе `422`). Пустое имя - без брокера; так же
брокер снимается при изменении. Так UI не нужен отдельный запрос «создать брокера» перед сохранением покупки, и
брокер не появляется в списке, если покупку в итоге не сохранили.

Ошибки: без `X-User-Id` - `401`; чужая или несуществующая покупка, неизвестная облигация - `404`; `quantity` вне
1..1 000 000, `buyPrice` вне 0,01..300 - `400` (bean validation); нет тикера, дата покупки в будущем, больше 200
покупок - `422`. Дату в будущем проверяет use case, а не `@PastOrPresent`: «сегодня» - по часовому поясу сервиса
(`DateTimeMapper.getNow`).

## UI (invest-api-ui)

Строка на облигацию и раскрытие покупок - см. «Строка на облигацию». 
`src/pages/PortfolioPage.tsx`, запросы - `src/api/portfolio.ts`, хуки `usePortfolio` / `usePortfolioMutations`.
Карточки итогов по валютам, таблица покупок (прибыль зелёная, убыток красный), окно добавления и изменения.

## Строка на облигацию

`PortfolioAggregator` (portfolio-service) сводит готовые модели покупок: `groups` - по тикеру в порядке покупок,
`totals` - по валюте. Свод только складывает суммы покупок, цены и курсы в нём не запрашиваются. Группировка на бэке,
а не в UI: правила сложения (средняя цена, `null` при неполной сумме) - в одном месте, как и итоги.

В UI (решения пользователя, 2026-11-08):

- Облигация с одной покупкой - строка и есть покупка: «изменить» / «удалить» и заплаченные рубли прямо в ней,
  стрелки нет. Раскрытие одной покупки отвергнуто: под строкой была бы вторая строка с той же покупкой.
- Несколько покупок - свод: стрелка, «N покупок» под тикером, средняя цена (подсказка в заголовке колонки),
  «N брокера» (имена в подсказке), диапазон дат; стрелка раскрывает покупки с их действиями.
- Строки не выглядят разнородными: на месте стрелки у одиночной строки - пустое место той же ширины (названия
  на одной линии), «+» (новая покупка этой облигации) у всех строк на одном месте, «изменить» / «удалить» -
  в одной колонке у одиночных строк и у раскрытых покупок, у строки-свода на их месте пусто.

## Купон и доходность к погашению

`getPortfolio` грузит облигации портфеля с графиками купонов и амортизации (`BondUseCase.getWithSchedule`, запрос на
облигацию). Доходность по цене покупки - `BondUseCase.getYieldToMaturityAtPrice`: копия облигации с текущей ценой =
номинал × цена покупки, дальше тот же `CouponCalculationService.calculateYieldToMaturity`, что считает
`yieldToMaturity` облигации при синхронизации. Свод получает купон и доходности через `BondMetrics` по тикеру.

## Рубли

У покупки и итога - `buyAmountInRub`, `currentAmountInRub`, `revenueInRub`:

- текущая стоимость × `PriceConversionService.getRubRate(currency)` - курс на сегодня, тот же, что у `currentInRub`
  облигаций (ЦБ, иначе budget.org, кэш 12 часов);
- стоимость покупки - `buy_amount_rub`, если пользователь указал, сколько заплачено в рублях; иначе
  стоимость покупки × `PriceConversionService.getRubRate(currency, buyDate)` → `CurrencyPriceUseCase.getRate` →
  `CurrencyRateHistoryUseCase.getRubRate` (currency-service): кэш `CURRENCY_RATE` → таблица `currency_rate` →
  `CbRfCurrencyUseCase.getCurrencies(date)` (`XML_daily.asp?date_req=`), ответ ЦБ сохраняется в таблицу целиком.
  Только ЦБ: у budget.org истории нет. Сохранение - `CurrencyRateStore.storeMissing` в своей транзакции
  (`REQUIRES_NEW`): курс запрашивается и из read-only транзакции чтения портфеля, где вставка запрещена. Ошибка
  сохранения только пишется в лог - курс уже получен, ответ не падает;
- доход в рублях - разница, итог - суммы по покупкам.

Каждая пара «валюта, дата» запрашивается один раз на запрос портфеля. UI показывает рубли только у нерублёвых сумм;
подпись «куплено на» убрана.

## Решения и отвергнутые варианты

- **Доходность к погашению по цене покупки - на сегодня, а не на дату покупки** (пользователь просил считать от
  средней цены покупки; у строки с покупками в разные даты одной даты покупки нет). Расчёт на дату покупки
  потребовал бы номинал и НКД на прошлую дату и учёт уже полученных купонов; можно добавить отдельно.

- **Сколько заплачено в рублях - общей суммой покупки** (решение пользователя, 2026-11-08), а не ценой одной
  облигации в рублях или курсом: сумму можно скопировать из отчёта брокера. Без НКД и комиссии - чтобы рублёвая
  стоимость покупки была той же величиной, что и стоимость покупки в валюте.
- **Свод - по облигации, а не по облигации и брокеру** (решение пользователя, 2026-11-08): одна облигация у двух
  брокеров - одна строка, брокеры видны в ней и в раскрытых покупках.

- **Курсы на дату - в таблице, а не только в кэше.** Решение пользователя (2026-11-08): курс на прошедшую дату не
  меняется; кэш в памяти пропадает при перезапуске, и портфель с покупками на разные даты делал бы запрос к ЦБ на
  каждую дату, а при недоступном ЦБ терял бы рубли. Кэш оставлен перед таблицей - он дешевле запроса в БД.

- **Доход в рублях - с курсом на дату покупки, а не доход в валюте × сегодняшний курс.** Пользователь (2026-11-08):
  рублёвый доход должен учитывать, по какому курсу валюта была куплена. Вариант «доход в валюте × курс сегодня»
  отвергнут: он теряет изменение курса и может показать убыток, когда в рублях прибыль.

- **Брокер - отдельная таблица, а не текст у покупки.** Иначе список для выбора пришлось бы собирать из покупок,
  и брокер пропадал бы вместе с последней покупкой; а «Т-Инвестиции» и «т-инвестиции» были бы разными.

- **Доход без купонов.** Нужен доход от цены покупки; купоны потребовали бы графика выплат по каждой покупке.
  Полный доход за период считает калькулятор.
- **Номинал - текущий для обеих сумм.** У облигаций с амортизацией номинал на дату покупки был больше, но тогда
  доход включал бы погашенный номинал как убыток. Процент дохода от номинала не зависит:
  `(текущая цена − цена покупки) / цена покупки`.
- **Отдельный модуль, а не в `alert-service`.** С уведомлениями у портфеля общий только пользователь.
- **Чтение мимо кэша облигаций.** Кэш держит всю выборку и сбрасывается после синхронизаций; портфелю нужны единицы
  тикеров - запрос `in (...)` с `join fetch` цены дешевле и всегда свежий.
