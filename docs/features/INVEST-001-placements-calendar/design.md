# INVEST-001: календарь размещений - исследование источника

Проведено 2026-11-15. Вопрос: есть ли бесплатный источник без ключа, из которого можно надёжно и автоматически брать
предстоящие размещения облигаций (эмитент, ориентир купона, срок, дата сбора заявок, рейтинг) - до того, как выпуск
появится в торгах.

**Итог: нет.** Официальные бесплатные источники (Мосбиржа ISS, T-Invest API) знают о выпуске, только когда он уже
зарегистрирован к торгам; книгу заявок и ориентиры купона публикуют платные сервисы и сайты-агрегаторы без открытого
API и без условий использования данных. Этап остановлен.

## Мосбиржа ISS (бесплатно, без ключа - уже используется)

| Что проверено | Результат |
| ------------- | --------- |
| Справочник ISS (`/iss/reference/`) - методы с «размещение», «книга заявок», placement, bookbuilding | отдельного метода предстоящих размещений нет |
| Режимы размещения рынка облигаций: `PACT` (аукцион, адресные заявки), `AUCT` (размещение, аукцион), `PAYT` (адресные заявки в CNY) | выпуск появляется в режиме только на день размещения; 15.11.2026 (воскресенье) - пусто. Ориентира купона и даты книги нет |
| Основной режим `TQCB`: выпуски без сделок или со статусом `N` | только старые неторгуемые выпуски, новых до размещения нет |
| `/iss/securities?is_trading=0` | неторгуемые - в основном погашенные и иностранные выпуски, а не будущие |
| Сервисы корпоративной информации `/iss/cci/...` (в том числе `info-nsd/securitybooks/bonds/securities` - справочник выпусков НКО НКД) | без подписки отвечают HTML-страницей вместо данных - это платный сервис |

Мосбиржа даёт данные с момента начала торгов (или с дня размещения) - этого достаточно для связи «размещение →
облигация», но не для календаря.

## T-Invest API (токен приложения уже есть)

У сообщения `Bond` есть `placement_date` и `placement_price`, у `Bonds` - параметр `instrument_status`
(`BASE` - то, что сейчас берёт синхронизация, `ALL` - все инструменты). Документация не говорит, попадают ли в `ALL`
выпуски до начала размещения. Ориентира купона, даты и времени книги заявок в API нет в любом случае.

## Cbonds (платно / по регистрации)

Метод `get_emissions` (`ws2.cbonds.info`, POST JSON с логином и паролем) содержит нужные поля: даты начала и конца
размещения, открытия и закрытия книги, ориентиры купона и доходности, ставку отсечения, ISIN, ИНН эмитента. Доступ -
после регистрации («Запросить доступ»), с офертами для физических и юридических лиц; бесплатности на странице API не
указано. Под правило «бесплатно, без ключа» не подходит.

## Сайты-агрегаторы

bonds-lab.ru, finolive.ru, corpbonds.ru, smart-lab.ru, sbersova.ru, bondcoupon.ru ведут календари первичных
размещений с датой книги, ориентирами и рейтингом. Не подходят:

- это HTML для людей, открытого API нет (bonds-lab упоминает API, но страница при проверке не открылась - условий
  нет); разбор вёрстки ломается при любом редизайне;
- сами берут данные из пресс-релизов организаторов и Cbonds - вторичный источник, полнота и задержка неизвестны;
- условия использования данных не опубликованы или не проверены; показ их данных в своём продукте за деньги -
  тот же юридический вопрос, что решение 0.1, только без договора.

## Что не проверено

- **T-Invest `Bonds` с `INSTRUMENT_STATUS_ALL`**: появляются ли в ответе выпуски с `placement_date` в будущем и за
  сколько дней до размещения. Запрос с токеном приложения при исследовании не выполнялся (не разрешён в сессии
  агента). Проверить вручную: вызвать `InstrumentsService/Bonds` с `instrumentStatus = INSTRUMENT_STATUS_ALL` и
  посмотреть выпуски, у которых `placementDate` позже сегодняшнего дня. Если их нет - вариант 2 из
  [README.md](README.md) отпадает.
- Страницы и условия bonds-lab.ru - сайт не ответил.

## Если этап продолжат

Набросок, чтобы не исследовать заново:

- источник - за интерфейсом `PlacementProvider` (как `PaymentProvider`), реализация на выбранный источник, ключ - в
  конфигурации;
- таблица `bond_placement`: эмитент (id Мосбиржи, если найдётся по ИНН через `bond_issuer`), название, ISIN (может
  появиться позже), номинал и валюта, срок, ориентир купона (от / до, `null` - не объявлен), финальный купон, даты книги
  и размещения, рейтинг (общая шкала `RatingScale`), статус `UPCOMING` / `BOOK` / `PLACED` / `CANCELLED`;
- связь с облигацией - по ISIN после синхронизации облигаций: найден в `bond` - размещение уходит из предстоящих;
- уведомление - новый тип `bond_alert` без облигации с фильтром по ступени рейтинга и типу купона, через очередь
  `notification`;
- публичный эндпоинт под `/bonds/**` (gateway уже пропускает без входа) и страница «Размещения» в UI.
