# INVEST-001: импорт от брокера

Статус: **в работе** - сделано 2026-11-14, этап 9 [дорожной карты](../../roadmap.md). Код не закоммичен; ветки - те,
на которых сейчас репозитории: invest-api `feature/INVEST-001`, invest-api-ui `feature/INV-001` (отдельную ветку
называет владелец). invest-gateway не меняется: `/api/portfolio/**` уже проксируется, в том числе multipart.

## Цель

Портфель заполняется без ручного ввода: покупки и продажи облигаций приходят от брокера и превращаются в сделки
этапа 8 ([INVEST-001-portfolio-income](../INVEST-001-portfolio-income/)). Главная фича платного тарифа.

## Объём

- **invest-api** - новый модуль `feature/import-service`:
  - импорт по токену T-Invest **только на чтение**: токен проверяется в T-Invest (`GetAccounts`: хоть один счёт с
    полным доступом - токен не принимается), хранится зашифрованным AES-256-GCM ключом из переменной окружения
    `IMPORT_TOKEN_KEY`; наружу - только последние 4 символа; без ключа импорт по токену выключен;
  - операции счёта (`GetOperationsByCursor`: исполненные покупки и продажи, комиссия отдельной операцией
    приклеивается к сделке) и позиции (`GetPortfolio`: остаток облигации, которого нет в истории сделок, - строка
    «проверить»);
  - файлы отчётов за интерфейсом `ReportParser`: свой шаблон CSV (любой брокер) и HTML-отчёт Сбербанка;
  - два шага: предпросмотр (строки со статусами, портфель не меняется) и подтверждение выбранных строк - покупки и
    продажи создаются через `PortfolioUseCase` / `PortfolioTradeUseCase` со всеми их проверками, каждая в своей
    транзакции; повтор сделки определяется по ключу импорта (`import_key`, уникален у пользователя);
  - облигации, которых нет в системе, - строки `UNKNOWN_BOND` и сводка `unknownBonds` в предпросмотре и отчёте;
  - фича тарифа `BROKER_IMPORT` (в конфигурации - у `premium`): без неё предпросмотр, подключение токена и
    подтверждение - `402`.
- **invest-api-ui** - вкладка «Импорт» на `/portfolio` (`?tab=import`): мастер «Источник → Предпросмотр → Отчёт»,
  подключение и отключение токена, выбор счетов и даты начала, загрузка файла CSV или отчёта Сбербанка, флажки строк,
  неизвестные облигации и предупреждения, последние импорты; подсказка «доступно в платном тарифе»; цель аналитики
  `portfolio_import_applied`.
- **invest-deploy** - переменная `IMPORT_TOKEN_KEY` из Secret `invest-secrets` (необязательна).

## Готово, когда

- [x] повторный импорт того же отчёта ничего не меняет (`PortfolioImportTest.csvImportAndRepeatChangesNothing` - CSV,
  `PortfolioImportTest.tinvestImport` - по токену: сделки второй раз - `DUPLICATE`, подтверждение ничего не создаёт);
- [x] облигации, которых нет в системе, показаны в отчёте импорта, а не теряются (строка `UNKNOWN_BOND` и
  `unknownBonds` - в предпросмотре и отчёте, те же тесты);
- [x] токен нельзя прочитать из БД и логов (`PortfolioImportTest.tinvestImport`: в `broker_connection` - только
  шифртекст `v1:...`, в ответах - последние 4 символа, в выводе приложения за тест токена нет;
  `ImportParsingTest.tokenCipherRoundTripAndBindsUser` - шифртекст привязан к пользователю, чужим ключом не
  расшифровать).

Правила - в [business-rules.md](../../business-rules.md#импорт-от-брокера), как сделано - в [design.md](design.md).

  за штуку, комиссия - в поле операции или отдельной `BROKER_FEE`; замещающие облигации (номинал в валюте, сделки в
  рублях). Тесты - на моке клиента.
- Проверить разбор на реальном HTML-отчёте Сбербанка: столбцы ищутся по заголовкам из описания отчёта, на настоящем
  файле не проверялись.
- Проверить мастер в браузере на стенде k3d (загрузка файла через gateway, ширина 375 px).
- Задать `IMPORT_TOKEN_KEY` в `.env` стенда (`openssl rand -base64 32`) - без него на стенде работает только импорт
  файлов. Смена ключа делает сохранённые токены нечитаемыми: пользователи подключают их заново.
- Следующие форматы отчётов (Т-Инвестиции XLSX, ВТБ, Альфа) - новые реализации `ReportParser`; XLSX потребует
  библиотеку разбора Excel.
