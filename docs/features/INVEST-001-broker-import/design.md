# INVEST-001: импорт от брокера - устройство

```
UI /portfolio?tab=import ──▶ gateway /api/portfolio/imports/** ──X-User-Id──▶ invest-api /internal/rest/portfolio/imports/**
                                                                                 │
                         BrokerConnectionUseCase (токен) · PortfolioImportUseCase (предпросмотр, подтверждение)
                                   │                                   │
        TokenCipher (AES-GCM) ── broker_connection        источник ─┬─ TinvestClient ──gRPC, токен пользователя──▶ T-Invest API
                                                                    └─ ReportParser: CsvReportParser, SberHtmlReportParser,
                                                                                     AlfaXlsxReportParser (XlsxReader)
                                                                              │ TradeCandidate
                                                          ImportItemResolver: облигация (uid / ISIN / тикер), цена в %
                                                          номинала, НКД и комиссия в валюте номинала, статус строки
                                                                              │
                                                          portfolio_import + portfolio_import_item (предпросмотр, отчёт)
                                                                              │ подтверждение
                                         PortfolioUseCase.create / PortfolioTradeUseCase.createSale (+ import_key)
```

## Модули

- `feature/import-service` (новый, зависит от `portfolio-service`, jsoup):
  - `config/ImportProperties` - `ru.invest.api.imports.*`: ключ шифрования, срок предпросмотра, пределы, пояс,
    адрес и таймаут T-Invest, имя брокера; неверный ключ (не 32 байта Base64) не даёт стартовать;
  - `crypto/TokenCipher` - AES-256-GCM, случайный IV, пользователь - AAD; формат `v1:<Base64(IV + шифртекст)>`;
  - `tinvest/TinvestClient`, `GrpcTinvestClient` - T-Invest API с токеном пользователя: на каждый вызов свой
    `ManagedChannel` с заголовком `Authorization`, закрывается после вызова; ошибки gRPC → `TinvestClientException`
    (код и описание, без заголовков);
  - `parser/ReportParser` + `CsvReportParser`, `SberHtmlReportParser`, `AlfaXlsxReportParser`; общая `TradeTable`
    (столбцы по заголовкам, строка → `TradeCandidate`, ключ строки; направление - из столбца операции или по знаку
    количества; валюта комиссии - из своего столбца) и `ReportValues` (кодировка, числа, даты, «покупка / продажа»);
    `XlsxReader` - ячейки листов XLSX через JDK (zip + StAX, внешние сущности XML запрещены, распакованное - до
    100 МБ);
  - `usecase/BrokerConnectionUseCase` - подключение, проверка «только чтение», отключение, счета;
    `PortfolioImportUseCase` - предпросмотр по токену и из файла, подтверждение, список, форматы;
    `ImportItemResolver` - кандидаты → строки импорта со статусами; вторым проходом - похожие на ручные сделки и
    продажи без покупок по FIFO; `refresh` - строки открытого позже предпросмотра, импортированные с тех пор.
- `portfolio-service` - `PortfolioUseCase.create(userId, request, importKey)` и
  `PortfolioTradeUseCase.createSale(userId, request, importKey)` (прежние методы - с `null`);
  `PortfolioIncomeCalculator.nominalAt(bond, date)` - номинал на дату для перевода цены в % (то же правило, что у
  полного дохода), `nominalCurrency(bond)`.
- `common` - `BrokerConnection`, `PortfolioImport`, `PortfolioImportItem` и репозитории; `import_key` у
  `PortfolioPosition` и `PortfolioSale`, `findImportKeys`; `PlanFeature.BROKER_IMPORT`; `ExceptionErrorCode.IMPORT_INVALID`.
- `ui-service` - `PortfolioImportController`, `ImportDtoMapper` (вручную: счётчики - словарь с ключами-перечислениями);
  `GlobalExceptionHandler`: `TinvestClientException` → `502`, файл больше предела → `413`, нет части `file` → `400`.
- `invest-api-dto` - пакет `dto.portfolio.imports`: `PortfolioImportDto`, `PortfolioImportItemDto`,
  `ImportUnknownBondDto`, `BrokerConnectionDto`, `BrokerAccountDto`, запросы `BrokerTokenRequest`,
  `TinvestImportRequest`, `ImportApplyRequest`, перечисления; `PlanFeatureDto.BROKER_IMPORT`.

## БД

Миграция `tables/019-portfolio-import.xml`:

- `portfolio_position.import_key`, `portfolio_sale.import_key` - `varchar(200)`, частичные уникальные индексы
  `(user_id, import_key) where import_key is not null`;
- `broker_connection` - `user_id`, `provider` (`TINVEST`), `token_encrypted`, `token_hint`, `created_at`,
  `updated_at`, `last_import_at`; уникальна по `(user_id, provider)`;
- `portfolio_import` - `user_id`, `source`, `file_name`, `status` (`PREVIEW` / `APPLYING` / `APPLIED`),
  `skipped_operations`, `warnings`, `created_at`, `applied_at`;
- `portfolio_import_item` - строка источника: `line_no`, `kind`, `import_key`, дата, тикер, ISIN, FIGI, название,
  количество, цена в %, НКД, комиссия, валюта номинала (`currency`, отдельный changeset), рубли, брокер, `status`,
  `message`, `trade_id`; удаляется вместе с импортом (`on delete cascade`).

## API

| Метод и путь (`/internal/rest/portfolio/imports`) | Что |
| --- | --- |
| `GET /tinvest` | подключение: включён ли импорт по токену, подключён ли токен, последние 4 символа, даты |
| `PUT /tinvest` `{token}` | подключить (заменить) токен: `200` со счетами; нет фичи - `402`; токен с правами на торговлю, не подошёл, без счетов, неверный формат, импорт выключен - `422`; T-Invest не ответил - `502` |
| `DELETE /tinvest` | удалить токен (`204`) |
| `GET /tinvest/accounts` | счета подключённого токена (заодно проверка «только чтение») |
| `POST /tinvest/preview` `{accountIds?, from?, broker?}` | предпросмотр по токену: `201` и импорт `PREVIEW` |
| `POST /file/preview?format=CSV\|SBER_HTML\|ALFA_XLSX&broker=` (multipart `file`) | предпросмотр из файла: `201`; файл не того формата, пустой, больше 5 МБ, строк больше `max-items` - `422` |
| `GET /file/formats` | форматы файлов, для которых есть разбор |
| `GET /` | последние 20 импортов без строк |
| `GET /{id}` | импорт со строками (у предпросмотра - строки, импортированные с тех пор, становятся `DUPLICATE`); чужой - `404` |
| `POST /{id}/apply` `{itemIds}` | создать выбранные строки: `200` и отчёт; уже подтверждён - `422` |

## Решения и отвергнутые варианты

- **Два шага: предпросмотр хранится в БД.** Подтверждение создаёт сделки по сохранённым строкам, а не запрашивает
  брокера заново: пользователь подтверждает ровно то, что видел. Неподтверждённые предпросмотры старше 7 дней
  удаляются при следующем импорте пользователя. Отчёт - тот же импорт после подтверждения.
- **Дубли - по ключу импорта у сделки, а не по совпадению полей.** У T-Invest ключ - счёт и номера биржевых сделок
  (id операции, по документации, может меняться), без номеров - id операции; у файла - номер сделки, а без него -
  хеш значений строки и номер повтора такой же строки в файле (две одинаковые сделки за день - две разные, тот же файл
  второй раз - те же ключи). Уникальный индекс `(user_id, import_key)` защищает от гонки двух подтверждений. Сделка,
  введённая вручную, ключа не имеет: похожая отмечается `POSSIBLE_DUPLICATE` и не выбрана по умолчанию. Точное
  совпадение (облигация, дата, количество) на проверке стенда пропустило дубли: вручную вводят другую дату или одну
  покупку вместо нескольких исполнений. Поэтому - три правила (business-rules.md): количество ± 7 дней, сумма
  исполнений дня, «не позже последней ручной сделки облигации». Ложное «похожа» дешевле пропущенного дубля: строку
  можно выбрать, а задвоенный лот надо искать и удалять. Совпадение по цене не используется - вручную цену тоже вводят
  округлённой. Одна и та же сделка из токена и из файла - разные ключи: так импортировать не нужно (сказано
  в правилах).
- **Сделки создаются теми же use case, что и вручную.** Все проверки этапа 8 (FIFO, дата, погашение, лимит тарифа
  покупок) работают и для импорта. Каждая строка - своя транзакция (`REQUIRES_NEW`): продажа, которой не хватает
  покупок, получает `FAILED` с причиной, остальные создаются. Покупки той же даты создаются раньше продаж. Такую
  продажу предпросмотр уже отмечает `NEEDS_REVIEW`: та же проверка FIFO (куплено к дате продажи ≥ продано к ней) по
  сделкам портфеля и новым строкам, выбранным по умолчанию.
- **Переход `PREVIEW → APPLYING` - условным `update`.** Два одновременных подтверждения одного импорта: второе получает
  `422`, а не создаёт сделки повторно. Непредвиденная ошибка строки - `FAILED`, сбой всего подтверждения - обратно
  `PREVIEW` (импорт не застревает в `APPLYING`; созданное повтор пропустит по ключу).
- **Токен проверяется на «только чтение» по `access_level` счетов** (`GetAccounts`): токен с полным доступом хотя бы к
  одному счёту отклоняется - даже если торговать им мы не стали бы, хранить его - лишний риск. Проверка повторяется
  при каждом предпросмотре.
- **Токен зашифрован ключом приложения, пользователь - AAD.** Утечка дампа БД без ключа токены не раскрывает;
  шифртекст, переписанный другому пользователю, не расшифруется. Ключ - только в переменной окружения. Токен не
  попадает в DTO-ответы, `toString` запроса и сообщения ошибок; bean validation на токене нет - чтобы отклонённое
  значение не попало в лог ошибок валидации.
- **Канал gRPC на каждый вызов, а не общий канал приложения.** Общий канал SDK несёт токен приложения в заголовках;
  перехватчик с токеном пользователя поверх него не убирает заголовок приложения. Канал на импорт - несколько запросов
  раз в несколько минут, накладные расходы не важны.
- **Остаток позиции без истории - строка `NEEDS_REVIEW`**, а не молча созданная покупка: дата (открытие счёта) и цена
  (средняя у брокера) приблизительны. Позиция меньше, чем по сделкам, у непогашенной облигации - предупреждение
  (вероятно, выкуп по оферте: его нужно ввести продажей по 100 %). С датой начала остатки не сравниваются - история
  неполная.
- **Цена T-Invest - в деньгах за штуку**, в % номинала переводится по номиналу на дату сделки (с учётом
  амортизации). Если валюта цены не валюта номинала (замещающие облигации), перевод - по курсу ЦБ на дату, а рубли
  покупки сохраняются как `buyAmountRub`. НКД и комиссия переводятся в валюту номинала по курсу ЦБ; курса нет - поле
  пустое (НКД - по графику, комиссия - 0) и пометка в строке.
- **Купоны, погашения и налоги из источника не импортируются**: портфель считает их сам по графику выплат
  (этап 8). Операции не по облигациям считаются в `skippedOperations`.
- **Формат файла выбирает пользователь**, а не определяет сервер: так понятнее сообщение «это не отчёт Сбербанка».
  Столбцы ищутся по заголовкам, а не по номерам - отчёты брокеров меняют порядок и состав столбцов.
- **XLSX без Apache POI.** Отчётам брокеров нужны только тексты ячеек; POI - десяток мегабайт зависимостей ради
  этого. Свой разбор - zip из JDK и StAX с запретом DTD и внешних сущностей, предел распакованного размера (защита от
  zip-бомбы). Даты и числа в отчёте Альфа-Банка - текстом; числовые даты Excel (серийные номера) не поддержаны.
- **Брокер - выбор пользователя при импорте**, по умолчанию - брокер источника. Ключ импорта считается от брокера
  источника, а не от выбранного: переименование брокера при повторном импорте не создаёт дублей. Имя сводится к уже
  заведённому брокеру пользователя по `ReportValues.header` (без регистра, пробелов и знаков) - и на бэке, и в UI по
  умолчанию: на стенде «Альфа-Банк» из отчёта завёл второго брокера рядом с ручным «АльфаБанк».
- **Рубли замещающих облигаций из отчёта.** Сумма сделки Альфа-Банка - в валюте расчётов и с НКД: при расчётах в
  рублях `buyAmountRub` = сумма − НКД (`TradeTable`, флаг «сумма с НКД»); у CSV - столбец «Сумма в руб». У рублёвой
  облигации не ставится - портфель такое отклоняет.
- **Открытый импорт - в адресе (`?tab=import&import=<id>`)**, а не в состоянии компонента: на стенде мастер однажды
  вернулся к первому шагу после подтверждения. Отчёт после подтверждения кладётся в кэш запроса сразу, портфель и
  тариф перечитываются в фоне, не задерживая показ.
- **Свой шаблон CSV вместо отчёта Т-Инвестиций (XLSX)**: CSV закрывает любого брокера (выгрузка в Excel и
  сохранение как CSV) без новой зависимости; клиентам Т-Инвестиций удобнее импорт по токену.
- **Лимит фичи, а не числа импортов.** Импорт - фича `BROKER_IMPORT`; созданные покупки по-прежнему считаются в лимите
  `PORTFOLIO_POSITIONS` (сверх лимита строка - `FAILED` с текстом `402`).
