# INVEST-001: Тарифы и права - как сделано

## Модули

| Где | Что |
| --- | --- |

`ui-service` (зависит от `account-service`). Так модули фич не зависят друг от друга.

## Действующий тариф

`ActivePlanResolver.resolve(userId)`: подписки, у которых `revoked_at is null`, `valid_from <= now`,
`valid_until is null or valid_until > now` (`now` - UTC); берётся последняя выданная. Нет такой - тариф по умолчанию.
Тариф подписки убрали из конфигурации - тоже тариф по умолчанию и предупреждение в логе: лучше урезать права, чем
отвечать 500.

Срок проверяется при каждом запросе - поэтому истечение не требует шедулера и ничего не меняет в данных.

Выдача (`grant`) отзывает действующие подписки (`revoked_at = now`) и создаёт новую с `valid_from = now`; подписка у
пользователя одна, история остаётся. `validUntil` в запросе - последний день включительно по поясу
`ru.invest.api.plans.zone` (Москва): в БД - начало следующего дня в UTC, в ответе - обратно день.

## Ответ 402

`GeneralPaymentRequiredException` → ProblemDetail: `detail` - для человека («Тариф «Бесплатный»: не больше 50 правил
уведомлений. В тарифе «Премиум» - до 500.»), `plan`, у лимита - `limit` и `max`, у фичи - `feature`. В подсказке -
первый по порядку настройки тариф, где лимит больше или фича есть; такого нет - без подсказки.

Лимит проверяется только при создании (`used >= max` → 402). Изменение, включение заново и удаление существующего
не ограничиваются: данные, созданные на прошлом тарифе, не удаляются и остаются рабочими.

## Решения и отвергнутые варианты

- **Тарифы в конфигурации, а не в таблице.** Их мало, меняются редко и вместе с релизом; лимиты читаются на каждой
  проверке без запроса в БД. В таблице подписок - только id тарифа.
- **Лимит 422 → 402.** Роадмап требует 402; UI по статусу отличает «нельзя по тарифу» от ошибки ввода.
- **Лимит брокеров (50) не перенесён:** это защита от мусора, а не свойство тарифа.
- **Подписка на календарь (`CALENDAR_ICS`) как первая фича-флаг:** единственная существующая фича, которую разумно
  сделать платной; в заготовке она в обоих тарифах, чтобы поведение не изменилось до решения 0.4. Проверка и в
  ленте `.ics`, иначе ссылка, созданная на платном тарифе, работала бы после его окончания.
- **Тариф по умолчанию не выдаётся (422):** «вернуть на бесплатный» - это отзыв подписки.
- **Без шедулера истечения:** статус вычисляется по сроку; шедулер понадобится этапу 7 для автопродления.

## Тесты

- `PlanTest` (интеграционный): тариф по умолчанию, выдача и отзыв сразу меняют лимит, 402 с полями, данные сверх
  лимита остаются, истёкшая и ещё не начавшаяся подписки не действуют, закрытая фича (создание ссылки и лента),
  замена подписки, тариф, убранный из конфигурации, ошибки выдачи (`422`, `400`, без `From`). Тарифы теста - в
  `app/src/test/resources/application.yml`; бесплатный совпадает с боевым, чтобы другие тесты создавали правила и
  покупки как раньше.
- `PlanPropertiesTest` (`ApplicationContextRunner`): верная настройка стартует; неизвестный тариф по умолчанию, нет
  тарифов, не все лимиты, отрицательный лимит, неверный id, пустое название, неизвестный лимит или фича - не стартует.
- UI: `plan.test.tsx` (страница), `portfolioPayments.test.tsx` (подсказка у закрытой подписки, 402 со ссылкой).
