# Реферальные ссылки брокеров: устройство

```
UI (карточка, калькулятор) ──GET /api/bonds/{ticker}/broker-links──▶ gateway ──▶ invest-api: BrokerLinkUseCase
                                                                                   └─ partners из конфигурации
клик ──POST /api/bonds/{ticker}/broker-links/{partnerId}/click (keepalive)──▶ gateway ──▶ broker_click +1
     └─ <a href=ссылка партнёра target=_blank rel="sponsored noopener noreferrer">
```

## invest-api

- Модуль `feature/broker-service` (зависит от `bond-supplier`): `BrokerReferralProperties`, `BrokerLinkUseCase`.
  Контроллеры - в `ui-service`: `BrokerLinkController` (`/internal/rest/bonds/{ticker}/broker-links`) и
  `BrokerClickMaintenanceController` (`/internal/rest/maintenance/broker-clicks`).
- Партнёры - в конфигурации, не в БД: их меняет владелец вместе с договором, раз в месяцы; админки нет. Настройка
  проверяется при старте (`@Validated`): id `[a-z0-9-]{1,64}`, название и рекламодатель не пустые, шаблон - `https://`
  без пробелов.
- Ссылка: подстановки `{ticker}`, `{isin}`, `{erid}` кодируются `URLEncoder` (UTF-8). Облигация ищется
  `BondUseCase.getByTickers` (лёгкий запрос с ценой и купоном, без графиков выплат). Партнёров нет - пустой список
  без запроса к БД, даже для несуществующего тикера: блок просто не показывается.
- Учёт: `broker_click (click_date, partner_id, ticker, clicks)`, уникальный ключ по трём полям, `+1` одним
  `insert ... on conflict do update` - параллельные клики не теряются. День - по `zone` (Москва). Выключенный или
  неизвестный партнёр и неизвестная облигация - `404`, ничего не пишется.
- Новый код ошибки `BROKER_PARTNER_NOT_FOUND`; миграция `tables/014-broker-click.xml`.

## invest-gateway

`POST /api/bonds/*/broker-links/*/click` добавлен в `PUBLIC_BOND_POSTS`. CSRF остаётся: UI шлёт `X-XSRF-TOKEN`, cookie
выдаётся и гостю. Клик гостя попадает в лимит анонимных запросов по IP - это и защита счётчика от накрутки.

## invest-api-ui

- `BrokerLinks` - один компонент для карточки и калькулятора. Запрос ссылок без повторов, `staleTime` 10 минут;
  пустой список или ошибка - `null`: реклама не должна ломать страницу.
- Клик: обычная ссылка в новой вкладке, а учёт - параллельный `POST` с `keepalive` через `useMutation`; сбой учёта
  пользователю не показывается и переходу не мешает.
- Маркировка: заголовок блока с пометкой «Реклама», у каждой ссылки «Реклама. {рекламодатель}. erid: {erid}»,
  `rel="sponsored"` для поисковиков, подпись «Это не инвестиционная рекомендация».

## Отвергнуто

| Вариант | Почему нет |
| ------- | ---------- |
| переход через редирект invest-api (`GET .../go` → `302` на партнёра) | учитывает и без JS, но ссылку видят и проходят поисковики и превью мессенджеров - счётчик накручивается; ещё один публичный маршрут в gateway; адрес партнёра не виден при наведении |
| партнёры в таблице БД | нужен CRUD и права администратора, а меняются они вместе с договором и выкладкой |
| счётчик в событиях аналитики этапа 4 | этапа 4 ещё нет; сверка с отчётом партнёра нужна в своей БД, а не во внешнем сервисе |
| хранить каждый клик с пользователем | для сверки достаточно числа по дню; персональные данные без нужды (152-ФЗ) |
| `navigator.sendBeacon` | не умеет заголовки - без `X-XSRF-TOKEN` gateway отвечает `403`; `fetch` с `keepalive` делает то же с заголовком |
