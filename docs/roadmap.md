# Дорожная карта: путь к монетизации

Будущие фичи всего проекта (invest-api, [invest-gateway](../../invest-gateway/docs/),
[invest-api-ui](../../invest-api-ui/docs/)), разбитые на этапы. Цель - чтобы продукт начал зарабатывать.
Составлен 10.11.2026 по документации трёх репозиториев; это план, а не описание системы - что уже сделано,
см. в [README.md](README.md).

Каждый этап - самостоятельное задание для ИИ-агента: его можно выдать целиком, со ссылкой на этот файл.

## Что мешает зарабатывать сейчас

- **Всё закрыто логином.** Gateway требует аутентификацию для всех маршрутов, кроме health: поисковики и ссылки,
  которыми делятся пользователи, ничего не видят.
- **Нет тарифов и оплаты.** Понятия «бесплатный / платный пользователь» в системе нет.
- **Права на данные не проверены.** Цены - из T-Invest API, новости и эмитенты - из ISS Мосбиржи. Разрешают ли их
  условия коммерческое использование и показ данных третьим лицам - не проверялось.

## Правила для каждого этапа

- Перед началом прочитать `docs/architecture.md` и `docs/business-rules.md` затронутых репозиториев.
- Документация - по общему контракту: папка фичи `docs/features/<id>-<название>/` (README.md со статусом, design.md),
  общие файлы (`architecture.md`, `business-rules.md`, `testing.md`, `deployment.md`) обновляются в том же изменении.
- Ветки git агент сам не создаёт - ветку называет владелец проекта.
- Принцип проекта сохраняется: величину, которую нельзя посчитать честно, отдаём `null`, а не приблизительно.
- Только бесплатные источники данных без ключа, если в этапе не сказано иначе.
- Новый код покрыт тестами по правилам `docs/testing.md`; изменения БД - миграциями Liquibase.
- Продукт только информирует: никаких формулировок «советуем купить / продать» (см. «Юридические ограничения»).
- Секреты (токены, ключи провайдеров) - только в конфигурации, не в коде и не в документации.

## Этап 1. Публичный режим

Статус: сделан 2026-11-10 - [INVEST-001-public-mode](features/INVEST-001-public-mode/); на публичном адресе включать
после решения 0.1.

**Цель:** список облигаций, карточка, новости и калькулятор открываются без входа.

- gateway: чтение `/api/bonds/**` (включая `POST .../page` и `POST .../calculation`) - без аутентификации;
  `/api/alerts/**` и `/api/portfolio/**` - как сейчас. `X-User-Id` из браузера по-прежнему затирается. CSRF для
  анонимных POST должен работать (cookie `XSRF-TOKEN` выдаётся и без сессии).
- gateway: ограничение частоты анонимных запросов по IP (защита от выкачивания данных).
- ui: состояние «гость»: кнопка «Войти» вместо профиля; страницы портфеля и уведомлений и кнопка уведомлений в
  карточке предлагают войти, а не падают с `401`. После входа - возврат на ту же страницу.
- api: без изменений.

**Готово, когда:** в окне инкогнито работают список с фильтрами, поиск, карточка с графиком, событиями и новостями,
лента и калькулятор; `/api/portfolio` и `/api/alerts` без сессии отвечают `401`; тесты gateway покрывают оба случая.

## Этап 2. SEO-страницы

Статус: сделан 2026-11-10 - [INVEST-001-seo-pages](features/INVEST-001-seo-pages/); как и этап 1, на публичном адресе
включать после решения 0.1.

**Цель:** поисковики индексируют страницы облигаций и эмитентов.

- ui: у каждой страницы свои `title`, `description`, canonical и Open Graph; читаемые адреса.
- Пререндер или SSR для страниц облигации, эмитента и подборок: поисковик должен получать готовый HTML, а не пустой
  SPA. Способ (пререндер при сборке, отдельный рендер-сервис, переход на SSR) агент выбирает и обосновывает в design.md.
- api: страница эмитента - `GET /bonds/issuers/{id}`: название, ИНН, его выпуски, новости (данные `bond_issuer` уже
  есть); эндпоинт со списком адресов для `sitemap.xml`.
- gateway / ui: `sitemap.xml` и `robots.txt`.
- Подборки-страницы на готовых фильтрах: «самые доходные ОФЗ», «флоатеры», «погашение в этом году».

**Готово, когда:** `curl` страницы облигации возвращает HTML с названием, ценой и доходностью; `sitemap.xml`
перечисляет все облигации и эмитентов; Lighthouse SEO не ниже 90.

## Этап 3. Реферальные ссылки брокеров

Статус: сделан 2026-11-11 - [INVEST-001-broker-referral](features/INVEST-001-broker-referral/); партнёров заполнить
после решения 0.3 (пока список пуст и блок не показывается).

**Цель:** первый доход - переход к брокеру из карточки облигации.

- api: брокеры-партнёры в конфигурации (название, шаблон ссылки, текст маркировки рекламы, включён ли);
  эндпоинт со ссылками для облигации.
- ui: блок «Купить у брокера» в карточке и в калькуляторе, с пометкой «Реклама» и данными рекламодателя из конфигурации.
- Учёт переходов: счётчик кликов по брокеру и облигации (таблица или события аналитики этапа 4).

**Готово, когда:** при пустом списке партнёров блок не показывается; с партнёром - ссылка ведёт по шаблону,
пометка видна, клик учитывается.

## Этап 4. Аналитика и лендинг

Статус: сделан 2026-11-12 - [INVEST-001-analytics-landing](features/INVEST-001-analytics-landing/); аналитика включится,
когда в сборке UI будет номер счётчика Метрики (после решения 0.5).

**Цель:** видеть, какими фичами пользуются, и объяснять продукт новому посетителю.

- ui: продуктовая аналитика (просмотры страниц, ключевые действия: фильтр, расчёт, добавление покупки, создание
  правила, подключение Telegram). Сервис - российский или свой (Яндекс Метрика либо self-hosted), без передачи
  персональных данных; баннер согласия, если сервис ставит cookie.
- ui: посадочная страница для гостя: что умеет продукт, скриншоты, кнопка «Войти / Зарегистрироваться».

**Готово, когда:** события видны в выбранном сервисе; гость на `/` видит лендинг, вошедший - список облигаций.

## Этап 5. Календарь выплат

Статус: сделан 2026-11-12 - [INVEST-001-payment-calendar](features/INVEST-001-payment-calendar/); подписку `.ics` в
настоящем календаре проверить на стенде с публичным адресом.

**Цель:** пользователь видит, когда и сколько денег придёт по его портфелю.

- api: `GET /portfolio/calendar?from=&to=` - будущие купоны, амортизация, погашения и оферты по покупкам портфеля
  (события считает существующий `BondEventUseCase`), сумма = выплата на облигацию × количество, итоги по месяцам и
  валютам, в рублях - по текущему курсу. Купон без объявленного размера - событие без суммы и флаг неполного итога.
- api: экспорт `.ics` (личная ссылка с токеном, чтобы календарь подписывался без сессии).
- gateway: маршрут уже покрыт `/api/portfolio/**`; для `.ics` по токену - отдельный публичный маршрут.
- ui: вкладка «Выплаты» в портфеле: по месяцам, столбики сумм, список событий.

**Готово, когда:** суммы календаря совпадают с вкладкой «События» карточки × количество; флоатер без размера купона
не занижает итог молча; `.ics` открывается в календаре.

## Этап 6. Тарифы и права

**Цель:** система различает бесплатного и платного пользователя (пока без оплаты).

- api: таблица подписок (пользователь, тариф, срок действия, источник), сервис прав `EntitlementUseCase`:
  лимиты и флаги фич по тарифу из конфигурации. Существующие лимиты (50 правил, 200 покупок) переводятся на него.
- api: `GET /account/plan` - тариф, срок, лимиты и их использование; превышение лимита - `402` с понятным описанием.
- api: maintenance-эндпоинт выдачи и отзыва тарифа вручную (для тестов и первых пользователей).
- gateway: маршрут `/api/account/**`.
- ui: страница «Тариф»: что входит, сколько использовано; подсказка «доступно в платном тарифе» у закрытых фич.

**Готово, когда:** смена тарифа через maintenance-эндпоинт сразу меняет лимиты; по истечении срока пользователь
возвращается на бесплатный тариф, данные сверх лимита не удаляются, но новые не создаются.

## Этап 7. Оплата

**Цель:** пользователь сам покупает и продлевает тариф.

- api: модуль платёжного провайдера за интерфейсом (как `NotificationSender` у уведомлений): создание платежа,
  приём webhook с проверкой подписи, идемпотентность, история платежей, автопродление и отмена.
- gateway: публичный маршрут webhook провайдера (без сессии, проверка подписи - в api).
- ui: покупка тарифа, статус платежа, отмена подписки, чеки; ссылки на оферту и политику персональных данных.
- По желанию - оплата через Telegram Stars в боте.

**Готово, когда:** в тестовом режиме провайдера оплата включает тариф, повторный webhook не продлевает его дважды,
отмена останавливает автопродление, неудачный платёж не меняет тариф.

## Этап 8. Полный доход портфеля

**Цель:** портфель показывает реальный доход, а не только изменение цены.

- api: продажи и погашения позиций (частичные тоже), комиссия брокера и уплаченный НКД у сделки.
- api: полученные купоны и амортизация с даты покупки - из графика выплат × количество на дату выплаты.
- api: итог: доход от цены + купоны + амортизация − комиссии − налог (ставка - как в калькуляторе), XIRR портфеля и
  каждой облигации; история закрытых позиций.
- ui: колонки и итоги полного дохода, вкладка «Сделки», форма продажи.

**Готово, когда:** для тестовой облигации с известным графиком полный доход совпадает с ручным расчётом и с
калькулятором дохода за тот же период; старые покупки без комиссии и НКД продолжают работать.

## Этап 9. Импорт от брокера

**Цель:** портфель заполняется без ручного ввода. Главная фича платного тарифа.

- api: импорт по токену T-Invest **только на чтение**: токен хранится зашифрованным, проверяется, что прав на
  торговлю у него нет; операции и позиции превращаются в сделки этапа 8; повторный импорт не создаёт дублей.
- api: импорт файлов брокерских отчётов - начать с одного-двух брокеров, формат за интерфейсом парсера.
- ui: мастер импорта: источник, предпросмотр сделок, что не распознано, подтверждение.

**Готово, когда:** повторный импорт того же отчёта ничего не меняет; облигации, которых нет в системе, показаны
в отчёте импорта, а не теряются; токен нельзя прочитать из БД и логов.

## Этап 10. Данные для скринера

**Цель:** фильтры и сортировки, которых ждут держатели облигаций.

- api: кредитный рейтинг эмитента и выпуска (из релизов АКРА и НКР, которые уже разбираются: хранить текущий рейтинг,
  а не только новость), единая шкала для сравнения агентств.
- api: дюрация (Маколея и модифицированная) - считается вместе с доходностью к погашению.
- api: ликвидность - средний дневной объём по свечам за 30 дней.
- api: спред к ОФЗ - доходность минус точка кривой бескупонной доходности на тот же срок (источник кривой - Мосбиржа).
- api: у флоатера - базовая ставка и премия, если источник найдётся; иначе `null`.
- api + ui: фильтры и сортировки по новым полям, по сектору, сроку до погашения, частоте купона, наличию оферты и
  амортизации; экспорт текущей выборки в Excel / CSV.

**Готово, когда:** новые поля есть в списке и карточке, участвуют в фильтрах и сортировке с `null` в конце;
расчёты описаны в `business-rules.md` и проверены тестами на известных примерах.

## Этап 11. Сохранённые фильтры и уведомления по фильтру

**Цель:** «сообщи, когда появится облигация под мои условия».

- api: сохранённые фильтры пользователя (название, параметры `BondParametersRequest`), CRUD, лимит по тарифу.
- api: новый тип правила уведомлений - по фильтру: после синхронизации цен сравнивается выборка с прошлой,
  уведомление - о новых облигациях в ней (не больше N за раз), через существующую очередь `notification`.
- ui: «Сохранить фильтр», список сохранённых, переключатель уведомлений.

**Готово, когда:** облигация, вошедшая в выборку после обновления цен, даёт одно уведомление; колебание около
границы фильтра не даёт потока сообщений (тот же приём с запасом, что у порогов цены).

## Этап 12. Аналитика портфеля

**Цель:** пользователь видит структуру и риск портфеля.

- api: `GET /portfolio/analytics`: доли по эмитентам, секторам, рейтингам, валютам, типу купона; средневзвешенные
  доходность и дюрация; лестница погашений по годам; концентрация (доля крупнейшего эмитента).
- api: чувствительность к ставке: изменение стоимости при сдвиге доходности на ±1 п.п. (через модифицированную дюрацию).
- ui: вкладка «Аналитика» с диаграммами.

**Готово, когда:** доли в сумме дают 100%; позиции без данных вынесены в «нет данных», а не пропадают.

## Этап 13. Монитор риска и дайджест в Telegram

**Цель:** пользователь узнаёт о проблемах эмитента и возвращается в продукт.

- api: правило «риски по портфелю» - одно на пользователя, для всех облигаций портфеля: снижение рейтинга,
  приостановка торгов, дефолт и технический дефолт (по новостям биржи и агентств, уже привязанным к эмитентам).
- api: дайджест портфеля раз в день или неделю: стоимость и её изменение, ближайшие выплаты, новости по бумагам.
- ui: настройки монитора и дайджеста на странице уведомлений.

**Готово, когда:** одно событие - одно уведомление на пользователя, даже если у него несколько выпусков эмитента;
пустой дайджест не отправляется.

## Этап 14. Календарь размещений

**Цель:** раздел о новых выпусках, которых ещё нет в торгах.

- Сначала исследование: бесплатный источник данных о предстоящих размещениях. Результат - в design.md; если
  надёжного источника нет, этап останавливается с отчётом, а не делается на ненадёжных данных.
- api: загрузка и хранение размещений (эмитент, ориентир купона, срок, дата сбора заявок, рейтинг), связь с
  облигацией, когда она появится в системе.
- api: правило уведомления «новое размещение» (с фильтром по рейтингу и типу купона).
- ui: страница «Размещения» - публичная.

**Готово, когда:** размещение после начала торгов связывается с облигацией и уходит из предстоящих.

## Этап 15. Публичный Telegram-канал

**Цель:** бесплатный канал привлечения с автоматическими постами.

- api: публикация в канал через существующий клиент Telegram: рейтинговые действия, решения по ключевой ставке,
  новые размещения, еженедельная подборка самых доходных по группам риска. У каждого поста - ссылка на страницу
  продукта.
- api: расписание и лимит постов в день в конфигурации; шаблоны текстов без оценочных суждений.

**Готово, когда:** пост не дублируется при перезапуске; при выключенном флаге в канал ничего не уходит.

## Этап 16. ИИ-сводки новостей

**Цель:** короткая сводка «что происходит с эмитентом» - фича платного тарифа.

- api: сводка по новостям и рейтинговым действиям эмитента за период через LLM API за интерфейсом; результат
  кэшируется и пересчитывается только при новых новостях; лимит запросов по тарифу.
- В сводке - только факты из новостей со ссылками на источники, без рекомендаций; пометка «составлено ИИ».
- ui: блок сводки в карточке облигации и на странице эмитента.

**Готово, когда:** без новых новостей повторный запрос не вызывает LLM; при недоступном LLM карточка работает,
блока просто нет.
